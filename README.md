# Mini Image Analyzer

Repository URL: https://github.com/123bruke/mini_Image_analyzer

A compact Python-based research sandbox for experimenting with machine-learning setup, notebook generation, and parameter-efficient fine-tuning on a CPU-only environment. Although the repository name suggests image analysis, the current active workflow is primarily focused on preparing and running a small Qwen-style language-model fine-tuning pipeline in Google Colab.

This project is useful for learning, prototyping, and testing how a small language model can be adapted with LoRA on limited hardware. It is designed to be simple, educational, and easy to extend.

---

## Overview

This repository contains a set of helper scripts that collectively support a small training workflow:

- environment and dependency checks
- model configuration setup
- notebook generation for Colab
- dataset preparation for instruction tuning
- LoRA-based fine-tuning with a CPU-only runtime
- validation and notebook repair steps

The project is intentionally lightweight. It is not a production-ready application, but a practical example of how to build a modular local ML experimentation workflow.

---

## Project purpose

The goal of this repository is to provide a minimal but usable foundation for:

- testing whether a machine-learning environment is correctly installed
- preparing a small instruction dataset
- loading a pretrained language model
- adapting it using LoRA
- running training on CPU for experimentation
- saving the fine-tuned adapter and tokenizer
- evaluating behavior before scaling to a larger system

This is especially useful for learners and researchers who want an approachable starting point before moving to more advanced or larger-scale ML projects.

---

## Current active workflow

The main workflow is centered around a CPU-only fine-tuning pipeline for a compact Qwen model:

1. Install required libraries
2. Validate the Python environment
3. Create a dataset of instruction-response examples
4. Load the pretrained model
5. Add LoRA adapters
6. Train on CPU
7. Save the adapter files
8. Evaluate model outputs
9. Download or reuse the saved adapter

This workflow is implemented in notebook-generation logic and associated helper scripts. The actual notebook is generated by `strter.py`, which prepares a training notebook that can be opened in Colab and executed step by step.

## Repository structure

- `strter.py`  
  Generates a notebook-style training workflow for CPU-only LoRA fine-tuning.

- `eval.py`  
  Reads and checks notebook code cells for possible issues before execution.

- `trans.py`  
  Handles model configuration and training setup.

- `model.py`  
  Sets the working directory and Google Drive output folders used in Colab.

- `liser.py`  
  Checks installed ML packages and prints environment details.

- `cheak.py`  
  Checks TPU support and environment compatibility.

- `README.md`  
  Project documentation and usage guide.

## What the scripts do

### `strter.py`
This is the core notebook generator. It builds a sequence of markdown and code cells that walk through:

- installing dependencies
- setting CPU mode
- mounting Google Drive
- creating a tiny training dataset
- loading `Qwen/Qwen3-0.6B`
- applying LoRA
- training the adapter
- saving model files
- evaluating generated responses

This file is useful for turning a conceptual workflow into a runnable notebook without writing all the notebook cells manually.

### `eval.py`
This script is designed to validate notebook cells, making sure they are structurally consistent and suitable for execution. It helps detect issues in generated notebook content before running the cells in a notebook environment.

### `trans.py`
This file contains configuration elements such as model selection, training settings, and experiment parameters. It centralizes the settings that affect the training process.

### `model.py`
This script prepares the runtime environment in Colab. It sets up:

- a working directory
- a folder for saved adapters
- access to Google Drive storage

This is helpful when you want fine-tuned artifacts to persist beyond a Colab session.

### `liser.py`
This helper script prints installed library versions and checks whether the environment has the expected ML stack. It helps confirm the runtime is ready before training starts.

### `cheak.py`
This script checks whether TPU support is available, which is useful if you want to compare CPU and TPU environments.

## Requirements

This project is built for Python-based experimentation and is intended to run in environments such as:

- Google Colab
- local workstation
- Linux or macOS development setup

Recommended requirements:

- Python 3.10 or newer
- PyTorch
- Transformers
- PEFT
- Datasets
- Accelerate
- Safetensors
- Google Colab utilities (for notebook workflow)

Install the primary ML packages with:

```bash
pip install -U transformers peft accelerate datasets safetensors
```

You may also need to install PyTorch depending on your environment.

## Quick start

### 1. Generate the notebook
Run:

```bash
python strter.py
```

This creates a notebook in the execution environment, typically a Colab runtime.

### 2. Open the generated notebook
In Google Colab, open the output notebook and choose a CPU runtime.

### 3. Run cells in order
The notebook is designed to be executed sequentially. The workflow includes:

- dependency installation
- dataset creation
- model loading
- LoRA setup
- training loop
- adapter saving
- evaluation

### 4. Validate notebook code
If needed, run:

```bash
python eval.py
```

This helps ensure the generated notebook content is in a valid format before execution.

### 5. Check environment
To inspect installed versions and available hardware:

```bash
python liser.py
```

### 6. Check TPU availability
Run:

```bash
python cheak.py
```

## Example training concept

The training flow is designed around a minimal instruction-tuning dataset. The script creates a few sample examples in a JSONL-style conversation format and uses them to fine-tune a model with LoRA.

Each example usually contains:

- a user question
- a system instruction
- an assistant answer

This format makes it possible to train a model to respond to user prompts in a supervised way. The training objective is to teach the model to produce the correct next tokens for the assistant response.

The repository intentionally keeps this setup small so it can run on limited hardware and be easy to understand.

---

## Model and training details

The workflow is based on a CPU-first training approach and uses:

- LoRA adapters
- supervised fine-tuning
- FP32 precision
- small dataset experimentation
- lightweight model adaptation

Important notes:

- This is LoRA fine-tuning, not QLoRA.
- The model is trained on CPU, which is much slower than GPU training.
- The included data examples are only for pipeline testing and learning.
- The saved LoRA adapter is not a complete full-model copy.
- Fine-tuning does not guarantee factual correctness or reliable reasoning.

---

## Expected outputs

When the workflow runs successfully, it produces:

- a small training dataset
- a pretrained model loaded in the environment
- LoRA adapter weights
- tokenizer files
- training metrics and loss values
- a saved output directory for the adapted model
- optional ZIP export for downloading the adapter

These outputs are useful for experiment tracking and comparing before/after model behavior.

---

## Training limitations

This repository is a research-oriented example, not a production-ready training stack. Some important limitations include:

- CPU training is significantly slower than GPU training
- Small demo datasets are not enough for a strong domain expert
- Validation metrics on tiny datasets can be noisy
- LoRA is useful for adaptation but not a replacement for careful data quality control
- This project is mainly for learning and experimentation

For serious applications, you should expand the dataset, add systematic evaluation, and use better validation strategies.
